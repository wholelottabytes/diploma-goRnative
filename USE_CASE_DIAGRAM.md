# 📊 USE CASE DIAGRAM - ПОЛНОЕ ОПИСАНИЕ

## 🎯 ACTORS (Акторы)

### 1. **Guest (Гость)**
Незарегистрированный пользователь.

**Цели:**
- Просмотреть каталог битов
- Поискать биты
- Зарегистрироваться

---

### 2. **User (Покупатель)**
Зарегистрированный пользователь с базовой ролью.

**Цели:**
- Всё что может Guest
- Оценивать биты (1-5 звёзд)
- Оставлять комментарии
- Покупать биты
- Добавлять в избранное
- Управлять профилем
- Стать продюсером

---

### 3. **Producer (Продюсер)**
Пользователь с расширенной ролью (user + producer).

**Цели:**
- Всё что может User
- Загружать новые биты
- Редактировать свои биты
- Удалять свои биты
- Просматривать статистику своих битов
- Получать доход с продаж

---

### 4. **Manager (Модератор)**
Пользователь с ролью модератора (user + manager).

**Цели:**
- Всё что может User
- Просматривать жалобы
- Обрабатывать жалобы (одобрить/отклонить)
- Удалять контент
- Блокировать пользователей

---

### 5. **System (Система)**
Автоматизированные процессы.

**Цели:**
- Проверка на плагиат
- Генерация аудиофингерпринта
- Отправка уведомлений
- Ведение статистики

---

## 📋 USE CASES (Варианты использования)

### 🏠 АНОНИМНЫЕ ДЕЙСТВИЯ (Guest)

#### UC-001: Регистрация
**Актор:** Guest  
**Предусловие:** Нет аккаунта  
**Основной поток:**
1. Guest открывает экран регистрации
2. Вводит email, password, name, phone
3. Нажимает "Register"
4. Система проверяет уникальность email
5. Система создаёт аккаунт с ролью "user"
6. Система автоматически авторизует пользователя

**Постусловие:** Guest становится User

**Альтернативы:**
- Email уже занят → ошибка "Email already exists"
- Слабый пароль → ошибка "Password must be at least 6 characters"

---

#### UC-002: Авторизация
**Актор:** Guest  
**Предусловие:** Есть аккаунт  
**Основной поток:**
1. Guest открывает экран входа
2. Вводит email и password
3. Нажимает "Login"
4. Система проверяет credentials
5. Система выдаёт JWT токен
6. Система перенаправляет на Home

**Постусловие:** Guest становится User

**Альтернативы:**
- Неверный email/password → ошибка "Invalid credentials"

---

#### UC-003: Просмотр каталога битов
**Актор:** Guest  
**Предусловие:** Нет  
**Основной поток:**
1. Guest открывает Home или Explore
2. Система показывает список битов (Trending / Latest)
3. Guest видит: title, author, price, tags, rating

**Постусловие:** Нет

---

#### UC-004: Поиск битов
**Актор:** Guest  
**Предусловие:** Нет  
**Основной поток:**
1. Guest открывает Explore
2. Вводит поисковый запрос
3. Система фильтрует по title, tags, description, author
4. Система показывает результаты

**Постусловие:** Нет

---

### 👤 ДЕЙСТВИЯ USER (Покупатель)

#### UC-101: Просмотр деталей бита
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User выбирает бит из каталога
2. Система показывает: title, author, price, description, tags, BPM
3. User может прослушать превью
4. Система показывает рейтинг и комментарии

**Постусловие:** Нет

---

#### UC-102: Оценка бита
**Актор:** User  
**Предусловие:** User авторизован, бит открыт  
**Основной поток:**
1. User нажимает на звезду (1-5)
2. Система сохраняет оценку
3. Система пересчитывает средний рейтинг
4. Система показывает подтверждение

**Постусловие:** Оценка сохранена

**Альтернативы:**
- User уже оценивал → оценка обновляется

---

#### UC-103: Добавление комментария
**Актор:** User  
**Предусловие:** User авторизован, бит открыт  
**Основной поток:**
1. User вводит текст комментария
2. User нажимает "Post"
3. Система сохраняет комментарий
4. Система показывает комментарий в списке

**Постусловие:** Комментарий добавлен

**Альтернативы:**
- Пустой текст → ошибка "Comment cannot be empty"

---

#### UC-104: Покупка бита
**Актор:** User  
**Предусловие:** User авторизован, есть баланс  
**Основной поток:**
1. User нажимает "Buy Beat"
2. Система показывает цену и тип лицензии
3. User подтверждает покупку
4. Система списывает средства с баланса
5. Система создаёт заказ
6. Система открывает доступ к скачиванию

**Постусловие:** Бит куплен, доступ открыт

**Альтернативы:**
- Недостаточно средств → ошибка "Insufficient balance"
- Бит уже куплен → сообщение "Already purchased"

---

#### UC-105: Добавление в избранное
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User нажимает "Like" на бите
2. Система сохраняет в избранное
3. Система показывает иконку "liked"

**Постусловие:** Бит в избранном

---

#### UC-106: Просмотр избранного
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User открывает раздел "Rated"
2. Система показывает список liked битов
3. User может перейти к деталям бита

**Постусловие:** Нет

---

#### UC-107: Просмотр профиля
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User открывает Profile
2. Система показывает: name, email, rating, balance, role
3. User видит меню навигации

**Постусловие:** Нет

---

#### UC-108: Редактирование профиля
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User нажимает "Edit Profile"
2. User изменяет name, phone, bio
3. User нажимает "Save"
4. Система сохраняет изменения

**Постусловие:** Профиль обновлён

---

#### UC-109: Стать продюсером
**Актор:** User  
**Предусловие:** User авторизован, роль "user"  
**Основной поток:**
1. User нажимает "Become a Producer"
2. Система показывает описание возможностей
3. User подтверждает
4. Система добавляет роль "producer"
5. Система показывает Add tab в навигации

**Постусловие:** User становится Producer

---

#### UC-110: Пополнение баланса
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User открывает "Top Up Wallet"
2. User вводит сумму
3. User выбирает способ оплаты
4. Система создаёт транзакцию
5. Система зачисляет средства

**Постусловие:** Баланс пополнен

---

### 🎵 ДЕЙСТВИЯ PRODUCER (Продюсер)

#### UC-201: Загрузка бита
**Актор:** Producer  
**Предусловие:** Producer авторизован  
**Основной поток:**
1. Producer открывает Add Beat
2. Producer выбирает аудиофайл
3. Producer выбирает изображение
4. Producer вводит: title, description, BPM, price, tags
5. Producer нажимает "Create Beat"
6. Система загружает файлы в MinIO
7. Система генерирует аудиофингерпринт
8. Система сохраняет метаданные в MongoDB
9. Система индексирует бит в Elasticsearch
10. Система проверяет на плагиат

**Постусловие:** Бит создан и опубликован

**Альтернативы:**
- Найден плагиат (>80% схожесть) → предупреждение
- Ошибка загрузки файла → ошибка "Upload failed"

---

#### UC-202: Редактирование бита
**Актор:** Producer  
**Предусловие:** Producer авторизован, бит создан  
**Основной поток:**
1. Producer открывает My Beats
2. Producer выбирает свой бит
3. Producer нажимает "Edit"
4. Producer изменяет поля
5. Producer нажимает "Save"
6. Система обновляет данные в MongoDB
7. Система обновляет индекс в Elasticsearch

**Постусловие:** Бит обновлён

**Альтернативы:**
- Чужой бит → ошибка "Access denied"

---

#### UC-203: Удаление бита
**Актор:** Producer  
**Предусловие:** Producer авторизован, бит создан  
**Основной поток:**
1. Producer открывает My Beats
2. Producer выбирает свой бит
3. Producer нажимает "Delete"
4. Система показывает подтверждение
5. Producer подтверждает
6. Система удаляет бит из MongoDB
7. Система удаляет индекс из Elasticsearch
8. Система удаляет файлы из MinIO

**Постусловие:** Бит удалён

**Альтернативы:**
- Чужой бит → ошибка "Access denied"

---

#### UC-204: Просмотр статистики
**Актор:** Producer  
**Предусловие:** Producer авторизован  
**Основной поток:**
1. Producer открывает Profile или My Beats
2. Система показывает для каждого бита:
   - Количество прослушиваний
   - Количество продаж
   - Общий доход
   - Средний рейтинг

**Постусловие:** Нет

---

#### UC-205: Управление каталогом
**Актор:** Producer  
**Предусловие:** Producer авторизован  
**Основной поток:**
1. Producer открывает My Beats
2. Система показывает список битов продюсера
3. Producer может фильтровать по статусу
4. Producer может перейти к редактированию

**Постусловие:** Нет

---

### 🛡️ ДЕЙСТВИЯ MANAGER (Модератор)

#### UC-301: Просмотр жалоб
**Актор:** Manager  
**Предусловие:** Manager авторизован  
**Основной поток:**
1. Manager открывает Manager Dashboard
2. Система показывает список pending жалоб
3. Система показывает статистику (pending, reviewed, resolved)

**Постусловие:** Нет

---

#### UC-302: Обработка жалобы
**Актор:** Manager  
**Предусловие:** Manager авторизован, есть pending жалобы  
**Основной поток:**
1. Manager выбирает жалобу
2. Manager видит: тип, причину, контент
3. Manager нажимает "Approve" или "Reject"
4. При Approve:
   - Система удаляет контент (если бит/комментарий)
   - Система помечает жалобу как "resolved"
5. При Reject:
   - Система помечает жалобу как "rejected"

**Постусловие:** Жалоба обработана

---

#### UC-303: Создание жалобы
**Актор:** User  
**Предусловие:** User авторизован  
**Основной поток:**
1. User открывает бит или комментарий
2. User нажимает "Report"
3. User выбирает тип: plagiarism, offensive, spam
4. User вводит причину
5. User нажимает "Submit"
6. Система создаёт жалобу со статусом "pending"

**Постусловие:** Жалоба создана

---

#### UC-304: Удаление контента
**Актор:** Manager  
**Предусловие:** Manager авторизован  
**Основной поток:**
1. Manager открывает жалобу
2. Manager подтверждает нарушение
3. Manager нажимает "Delete Content"
4. Система удаляет бит/комментарий
5. Система уведомляет автора

**Постусловие:** Контент удалён

---

### 🤖 ДЕЙСТВИЯ SYSTEM (Автоматические)

#### UC-401: Генерация аудиофингерпринта
**Актор:** System  
**Триггер:** Загружен новый бит  
**Основной поток:**
1. Система получает аудиофайл
2. Система запускает fpcalc
3. Система получает fingerprint строку
4. Система сохраняет fingerprint в MongoDB
5. Система помечает статус как "generated"

**Постусловие:** Fingerprint сгенерирован

---

#### UC-402: Проверка на плагиат
**Актор:** System  
**Триггер:** Сгенерирован fingerprint  
**Основной поток:**
1. Система получает fingerprint
2. Система сравнивает с существующими
3. Система вычисляет процент схожести
4. Если схожесть >80%:
   - Система помечает бит как "potential plagiarism"
   - Система создаёт жалобу автоматически

**Постусловие:** Проверка завершена

---

#### UC-403: Ведение статистики
**Актор:** System  
**Триггер:** Событие (просмотр, покупка, оценка)  
**Основной поток:**
1. Система получает событие
2. Система записывает в ClickHouse (beat_events)
3. Система обновляет агрегированные метрики

**Постусловие:** Статистика обновлена

---

#### UC-404: Отправка уведомлений
**Актор:** System  
**Триггер:** Событие (покупка, комментарий, жалоба)  
**Основной поток:**
1. Система определяет получателя
2. Система создаёт push-уведомление
3. Система отправляет уведомление

**Постусловие:** Уведомление отправлено

## 🔗 ОТНОШЕНИЯ (Relationships)

### Include (Включает):
- **UC-104 Покупка бита** `<<include>>` **UC-110 Пополнение баланса** (если недостаточно средств)
- **UC-201 Загрузка бита** `<<include>>` **UC-401 Генерация fingerprint**
- **UC-201 Загрузка бита** `<<include>>` **UC-402 Проверка на плагиат**

### Extend (Расширяет):
- **UC-304 Удаление контента** `<<extend>>` **UC-302 Обработка жалобы** (если Approve)
- **UC-102 Оценка бита** `<<extend>>` **UC-101 Просмотр деталей** (опционально)
- **UC-103 Комментарий** `<<extend>>` **UC-101 Просмотр деталей** (опционально)

### Generalization (Обобщение):
- **User** `--|>` **Guest** (User наследует все use cases Guest)
- **Producer** `--|>` **User** (Producer наследует все use cases User)
- **Manager** `--|>` **User** (Manager наследует все use cases User)
